# Biryani Legends: real-asset handoff

**For the agent (or person) picking this up on a local machine with open
network access.**

## Where things stand

`components/biryani-legends-template` is finished and ships with art made in
code:
- three drawn SVG engravings (harbour, fort, garden)
- three canvas-painted pots of biryani
- a generated paper grain

The template already accepts real assets. Nothing in the component needs to
change; only the data does.

The session that built the template could not fetch images:
- Canva and Adobe download hosts, Unsplash, Pexels and Wikimedia were all
  blocked by its network.
- Adobe Stock "free" images were rejected. Their licence does not allow
  redistributing the image file inside a publicly installable component.

**The rule for every asset:** public domain, CC0, or generated by you. No
watermarks. No stock licences. Keep a note of each asset's origin in the
table at the end of this file.

## Processing (Python 3 + Pillow, run locally)

Make one folder per asset and keep the originals.

```python
# cutout_pot.py  in.png out.webp  -> transparent, cropped, 1000 x 1000 WebP
import sys
from PIL import Image, ImageFilter, ImageChops
im = Image.open(sys.argv[1]).convert("RGB")
bg = Image.new("RGB", im.size, im.getpixel((4, 4)))           # flat background colour
diff = ImageChops.difference(im, bg).convert("L")
mask = diff.point(lambda v: 255 if v > 22 else 0).filter(ImageFilter.MaxFilter(3)).filter(ImageFilter.GaussianBlur(1.2))
out = im.convert("RGBA"); out.putalpha(mask)
out = out.crop(out.getbbox())
side = max(out.size); sq = Image.new("RGBA", (side, side)); sq.paste(out, ((side - out.width) // 2, (side - out.height) // 2))
# The template expects the rim to fill about 70% of the square, with the handles inside it:
pad = int(side * 0.06); canvas = Image.new("RGBA", (side + pad * 2,) * 2); canvas.paste(sq, (pad, pad))
canvas.resize((1000, 1000), Image.LANCZOS).save(sys.argv[2], "WEBP", quality=86, method=6)
```

If the background is not flat, use any matting tool you are licensed for,
such as `rembg` (MIT), and then run the crop and pad steps above.

```python
# ink_to_alpha.py  in.png out.webp  -> engraving lines as opaque ink, paper transparent
import sys
from PIL import Image, ImageOps
g = ImageOps.autocontrast(Image.open(sys.argv[1]).convert("L"), cutoff=1)
alpha = ImageOps.invert(g).point(lambda v: min(255, int(v * 1.35)))  # dark ink -> opaque
ink = Image.new("RGBA", g.size, (58, 46, 34, 255)); ink.putalpha(alpha)  # sepia-graphite ink
w = 2400; ink.resize((w, round(g.height * w / g.width)), Image.LANCZOS).save(sys.argv[2], "WEBP", quality=88, method=6)
```

The paper texture only needs a 512 × 512 crop, then `quality=82`.

Budget: pots 60–140 KB each, engravings 120–300 KB each, and paper under 60 KB.

## Wiring

Host the files in the installing app, for example in `public/legends/`. Then
pass them as data. Do **not** put them in `components/`: only the `.tsx`,
the demos and the README live there.

```tsx
import BiryaniLegendsTemplate, { BL_LEGENDS } from "@/components/ui/biryani-legends-template"

const legends = BL_LEGENDS.map((l, i) => ({
  ...l,
  dish: { ...l.dish, src: ["/legends/faiza-handi.webp", "/legends/selvarajan-clay.webp", "/legends/sonia-enamel.webp"][i] },
  engravingImage: [
    { src: "/legends/tellicherry.webp", aspect: 3.0, alt: "Engraving of the harbour at Tellicherry" },
    { src: "/legends/ambur-fort.webp", aspect: 1.85, alt: "Engraving of a hill fort above a river" },
    { src: "/legends/lucknow-garden.webp", aspect: 1.4, alt: "Engraving of a Nawabi garden" },
  ][i],
}))

<BiryaniLegendsTemplate legends={legends} paperTexture="/legends/paper.webp" />
```

Notes on how the template treats these assets:
- Pots: the template shows the image square, centred on the pot's position,
  with the page-drawn shadow under its middle 70%. A pot whose rim fills about
  70% of the frame lines up with that shadow, so keep the padding step.
- Engravings: they sit inside the layout's box (bottom band, top-right oval
  or top-left oval), are masked soft at the edges, and are revealed by an ink
  sweep. Opaque white grounds will show as white blocks, so always run
  `ink_to_alpha.py`.

Before publishing a demo that uses these assets, check:
- `npm run dev` in both `#biryani-legends-template` and `?dark` mode
- a phone viewport (one page at a time)
- `node tests/biryani-legends-template.test.mjs`

To ship the photos inside the published 21st demo itself, they must be
installable. Either:
- reference them by absolute HTTPS URL from a host you control (the 21st
  cover capture will then need a supplied `--preview`), or
- embed them as `data:` URIs in a demo file.

Keep the component file itself free of them.
